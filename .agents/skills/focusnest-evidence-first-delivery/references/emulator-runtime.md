# 模拟器测试环境与驱动

用于 AI、页面和存储流程的模拟器集成/正式包测试。保护服务故障走 Android 调试技能；签名、安装包一致性、凭据传递和附件操作走同目录的 `apk-and-release.md`。

## 先确认测试实际到达产品

安装/切换测试包、正式包后，重新检查目标包的配置。宿主本地服务已保存密钥，不代表 Android 原生通道也已配置。先读不含密钥的配置状态，再在已有授权下通过设置或测试通道配置并测试连接。初始包缺少配置只能记录为环境前提不足；没有取证时，不断言是测试运行器清掉了数据。

重启或切换页面后，在有时限的轮询中确认目标包前台、当前页面及目标控件可用，再执行下一步。仅等待固定三秒，或者仅确认进程存在，都不足以证明页面已准备好；超时保留现场并报告，不盲点旧坐标。

ADB 等驱动输入后，先比较实际字段内容与预期测试输入，再发送。长文本可能被截断，脚本调用成功不保证输入完整；必要时分段输入或使用已有可靠输入方式。敏感字段的比较仅在内存内完成，输出脱敏结果。输入框清空还需结合新消息和实际结果判断成功。

## 区分失败层级

按证据区分驱动输入/定位、缺少配置、网络/认证、模型结果与程序校验。环境或工具失败不计为产品失败，也不计为场景通过。修复前提后重跑相应断言；从检查点续跑时，确认真实状态仍连续，保留中断及恢复记录，不能把未验证步骤补记为成功。

先用固定响应验证程序分支，再用已授权的真实接口验证语义，最后在实际交付包上复测核心缺陷。示例替身不充当联网失败的成功兜底。具体次数由本轮边界决定，不强制复制某个历史测试时长或完整旧套件。

## 控制构建与采集成本

同一工作树的 Flutter 分析、测试和构建按项目要求串行，避免生成的注册文件互相覆盖；集成测试后使用项目指定的正式构建步骤。只改技能/文档时验证技能、链接和包内容即可。

等待测试时用少量进度信号；异常才采一次能区分原因的前台、配置、日志或截图，减少重复整页 UI dump。若证据显示主机内存不足，可在构建确已结束后停止本轮遗留的构建守护进程；保留用户应用与正在执行的构建。
