历史补验源标签为 `v0.2.7-demo.2`，提交 `c70624fcb85f7d2f7c04cdb1e1514b0b896ffee7`，运行包仍为 0.2.7+11。权威摘要是目标仓库的 `docs/validation/0.2.7-stability-2026-10-16.json`，方法见 `docs/稳定性验收.md`。这些路径用于回项目追溯；携带技能到其他项目后，使用目标项目自己的证据，不要求依赖此私有仓。

这里没有证明原会话在长锁屏后仍处于有效期并拦截，也没有现场看到到期瞬间撤去可见提醒。最后运行采样为 15:56:49，首次停止快照为 15:58:30；报告区间而非编造精确解除延迟。独立后续会话另测重新拦截与两轮退出，取消计数在恢复工作后补核，未描述成取消瞬间连续观察。

## 把观察转换成结论

| 实际证据 | 可以报告 | 仍需另测 |
| --- | --- | --- |
| 最终包启动新会话，真实到期并恢复完成记录 | 最终包新会话的完整计时路径通过 | 同版本其他 APK、升级恢复和所有设备 |
| 锁定期间服务从运行变为停止，解锁后放行 | 锁定条件下的到期解除结果 | 未覆盖时间窗内的精确延迟、可见提醒瞬间撤除 |
| 返回小屋后记录和喂食反馈，反复进入计数稳定 | UI 可见恢复与重复结算检查 | 全部 SQLite 内容一致、未观测操作期间的每个变化 |
| 新独立会话可拦截、两轮退出并出现取消记录 | 新一轮开始/退出路径可用 | 原到期会话在长锁屏后继续拦截 |

先确认用户会话，再开自由专注等独立测试；不要通过修改用户任务或恢复旧数据库制造条件。完成/取消测试按真实结果留下记录。只保存脱敏的必要结论，时间不确定、补核与工具干扰显式标注。

## 已有接口比空壳扩展更有用

用户要求“留接口、以后扩展”时，先核对当前端口及注入位置，说明现有契约能做什么、还缺什么，再决定是否需要改运行代码。此项目现有 7 类端口已经覆盖上下文、受控动作、智能建议、事件、设备、时钟与存储；具体定义以 `lib/core/ports.dart` 和实际适配器为准，详见目标仓库 `docs/扩展接口.md`。

尤其检查：同步缓存读取不等于可直接接远程请求；内存事件不等于可靠消息队列；事件 payload 不一定包含完整业务数据；其他平台需要各自原生实现。给具体需求预留适配器位置和兼容约定，保留禁用/模拟实现，不为未来可能性添加万能执行器或开启大模型/Agent。
