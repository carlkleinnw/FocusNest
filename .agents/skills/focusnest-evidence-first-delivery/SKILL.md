# 伴学小屋：先验证核心场景，再交付

先按当前项目 AGENTS.md 的顺序读取文档，核对 Git、实际代码、手机安装版本及当前专注。交接和历史技能仅用于选择检查项，冲突时以当前代码与用户指示为准。保留已有修复、本机数据和用户真实专注，独立记录测试会话。

## 决策顺序

1. 在改代码前复现本轮确切失败动作，记录包 stopped/退出原因、权限与绑定、实际提醒结果。普通 Home、单卡划除和设置强停分开。
2. 背景保护问题优先使用 `android-accessibility-focus-debugging`；需要选开源方案时使用 `android-protection-source-audit`。小米自启动和省电无限制分别核对；2026-10-15 在特定设备上避免强停的成功不自动成为当前设备的保证。
3. 依据已核实的可行路径做最小修改。继续保持一个页面一个核心功能、组件可复用、大模型与 Agent 首版禁用；白名单依旧是用户明确允许的少数应用，启动时冻结，必要系统应用放行。首次权限说明、拒绝路径与失效恢复分别验证，正常已授权打开减少重复弹窗。
4. 用最终安装的同一 APK 验收，再决定候选或交付。签名与发布操作时读取 [APK 与版本交付](references/apk-and-release.md)。

## 同包真机判据

记录 APK 版本/构建号、SHA-256、签名证书以及设备和所需系统设置。安装前比较证书，不匹配就停止覆盖，找回原签名；保留数据库，不以卸载或清数据绕过签名检查。

至少覆盖本轮核心失败动作、直接出现且持续遮挡的提醒、知道了返回桌面、重复打开、横竖屏、必要设置/拨号器、正常到期及退出放行。涉及后台留存时按本轮风险增加锁屏/长时间场景，不自动清除其他用户任务或重启手机。测试工具的操作串行，区分产品失败与自动化干扰。

验收记录明确四类：本轮最终包实测、较早候选结果、沿用旧版证据、尚未验证。恢复的旧会话到期不冒称新包独立运行完整时长；界面在后台不冒称 UI 进程已死。核心场景未通过时保留候选，不能用编译、单测或重开应用后的恢复代替。

补最终包完整会话、长锁屏或恢复结算时，读取 [稳定性证据与扩展边界](references/stability-evidence.md)。遇到附件传输失败，按 [APK 与版本交付](references/apk-and-release.md) 的分阶段核对与重试方式处理。

## 完成条件

当前授权范围内的修改与验证完成；报告实际通过与限制，版本记录和附注标签按项目 AGENTS.md 执行。推送/发布沿用当次授权，技能本身不新增外部操作授权。交付说明提交、标签、已推送分支、远端默认分支是否包含修改，并区分本地与远端证据。发布清单每一项都应能在相应交付位置找到，附件下载后核对哈希；私密手机资料与签名私钥不进入源码、日志或包。
