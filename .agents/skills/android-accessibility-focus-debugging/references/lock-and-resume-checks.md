# 锁屏、到期与恢复操作

适用于无障碍保护的长时测试、通知/来电干扰及中断后继续操作。先沿用用户当前授权，保留其进行中会话；以下方法不新增控制手机、取消会话或改变系统设置的授权。

## UI 操作从当前状态开始

- 长时等待、用户插话、来电或恢复工作后，旧截图和坐标立即视为过期。重新核对目标设备、当前用户锁定状态、实际前台和本应用会话，再决定下一步。
- 坐标操作前确认预期应用和页面；同一应用内的滚动、对话框或屏幕方向变化后仍需重定位。截图函数也要核对预期前台，防止把用户切换后的第三方页面或通知保存为验收图。
- 当前窗口属于来电、锁屏或用户正在使用的其他界面时，先让出操作。需要系统凭据解锁时由本人完成，恢复测试后再核对状态，不沿用旧会话判断。
- 同一手机的操作和采集串行。发现工具导航、解锁或通知改变了被测条件时，保存简短原因，将该片段排除或按实际条件单独报告。

## 分开观测三个状态

| 状态 | 观测及含义 |
| --- | --- |
| 当前用户锁定 | 例如可识别的 `dumpsys trust` 当前用户行。通知亮屏不等于已解锁；格式无法识别则保留 unknown |
| 物理屏幕 | 对照电源与显示状态。2026-10-16 HyperOS 曾同时报告 `mWakefulness=Dozing`、物理屏幕 OFF；不能只接受 Asleep。这里的 Dozing 不证明 Android 深度设备空闲模式 |
| 专注期限与保护 | 到期前观察保护，越过期限后应解除。不能把锁屏结束后服务已按期限停止误判为后台保护失败 |

锁屏通知可以短暂点亮屏幕，仍算锁定，但应报告亮屏采样数；实际解锁则打断连续锁屏条件。一次状态采样不能证明两个采样点之间的每一瞬间都没有变化。

## 先安排时间，再启动测试

将启动/权限检查、横竖屏、划除、锁屏、解锁后的拦截和自然到期排到同一条真实时间线上。若要求在原会话到期前验证长锁屏后拦截，要预留操作和本人解锁时间；若锁屏将跨到期，改为核对锁定期间到期、解锁后放行，另开独立测试确认保护可重启，按这个更窄的范围报告。

计时使用单调时钟计算间隔，并记录带时区的墙钟时间供对照。不得为赶进度修改手机时钟或借用网页快进。

采样循环应先读取并记录状态，再判断是否已到观察终点；终点、超时和异常退出均保留最后一次真实采样。仅“睡到截止时间后跳出循环”会漏掉终点变化。记录最后仍受限/仍运行与首次已放行/已停止的时间区间；没有覆盖到期窗口的观察，不能宣称测出了精确解除延迟。

## 结论和成本

USB 供电且持续连接 ADB 的锁屏观察不能替代无充电条件、深度待机、多日运行或耗电测试。确认这些前提后再选择下一轮测试，不为普通补验自动升级成电量基准测试。

优先报告“实际动作、设备条件、业务结果、观察时间范围”。设置开关、绑定、进程与前台服务仅为分层证据，最终仍要检查实际拦截或到期放行。
