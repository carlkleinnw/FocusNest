# 稳定性补验与证据边界

本轮目标是在已经交付的 0.2.7+11 同一 APK 上，补齐“最终包新建会话完整运行 30 分钟”的证据，延长锁屏观察，并核对恢复结算。此页说明验收方法；实际是否通过和执行时间以 [2026-10-16 补验记录](validation/0.2.7-stability-2026-10-16.json) 为准，不能仅凭本文推断已完成。

## 前置核对

- 核对当前代码与分支、已安装包版本/构建号，并比较安装 APK、本地交付 APK 和原验收记录的 SHA-256；核对证书，不为补验重装应用。
- 先在应用内确认现有会话。正在进行的用户专注保留；仅在没有进行中用户会话时开启独立测试，不编辑用户任务来制造测试条件。
- 无障碍开关、实际连接、自启动和省电策略分别核对。绑定表未明确输出组件时保留 unknown，结合应用状态与实际拦截判断，不把标签行当作绑定证据。
- 来电和用户正在使用手机时让出界面。所有手机操作串行，不使用 UIAutomator 暂停其他无障碍服务，不改真实时钟。

## 一次完整会话

1. 在最终 APK 内手动开始新的 30 分钟自由专注，记录开始时间和设备时钟；不沿用跨升级恢复的会话，也不使用网页快进。
2. 验证竖屏提醒、持续遮挡、重复打开和「知道了」真实返回桌面；横屏游戏提醒持续至少 30 秒。必要设置、系统跳转后的应用信息及拨号器仍可进入，不实际拨打电话。
3. 仅划除伴学小屋自己的最近任务卡片；核对产生新的退出时间、退出原因、包 stopped、权限和保护服务。未重开小屋前直接打开受限应用，实际出现提醒才记录恢复成功。其余任务保持原样。
4. 锁屏约 20 分钟，间隔采样屏幕状态、当前用户是否锁定与本应用保护状态。锁屏通知亮屏和实际解锁分别记录；发生解锁的片段不计为完整锁屏。采样不能证明任意两次采样之间都没有瞬间变化。连接 USB 充电的观察不算耗电测试，也不能当作深度待机验证。
5. 到期前保持小屋界面不在前台，观察前台保护服务按真实期限停止、受限应用恢复访问，期间不靠重新打开小屋触发放行。若解锁时会话仍在，检查实际拦截及到期撤提醒；若锁屏已经覆盖自然到期，检查锁定期间的到期状态、解锁后放行，再在独立新会话检查保护重新启用。后者不能写成“20 分钟锁屏后仍在原会话内拦截”或“现场看到到期撤除提醒”。
6. 回小屋检查完成结果、记录和喂食；再次离开和返回，确认可见结果不重复结算。仅 UI 核对到的内容记录为 UI 证据，不声称已完整审计 SQLite 或精确比较全部用户数据。
7. 另开独立测试会话，验证两轮提前退出与取消后放行；只结束自己的测试。完成与取消测试产生的记录按实际保留，不为清理测试痕迹删用户记录或回写旧数据库。

## 结果与发布

- 检查点标明通过、失败、受工具干扰或未验证。失败项不被后续普通打开成功覆盖；原 0.2.6 候选失败和 0.2.7 首轮记录保持原样。
- 若核心项失败，保留候选状态并按确切失败动作定位。若只补证据和文档，应用版本、构建号及原 APK 不变，使用新的附注文档修订标签。
- 脱敏摘要记录设备/固件、包哈希、测试条件、真实时间范围、结果与限制；不提交数据库、完整名单、用户任务标题、截图、通知、原始系统转储、凭据或签名私钥。
- 本机通过不推出其他品牌、重启、清全部任务、真正强停、零延迟或长期耗电通过。新增设备和更长场景需要独立补验。

扩展实施位置与兼容约定见 [扩展接口](扩展接口.md)。此轮的稳定性补验不启用大模型或 Agent，不增加新系统权限或高权限守护。
