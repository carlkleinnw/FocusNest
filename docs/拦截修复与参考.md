# 0.2.3 拦截验收与设计参考

用户验收：专注中打开白名单外应用，提醒直接显示在该应用上方并持续挡住操作；点击「知道了」返回桌面；再打开同一应用仍拦截。打开伴学小屋不是触发提醒的必要步骤。电话、桌面与必要设置保持可用，期限结束或本人两轮确认退出后放行。

已定位并分别验证的问题：

1. 旧状态机把任意应用窗口通知当作当前应用，未知/辅助窗口可误撤提醒。先用实际状态机复现失败，再改为实际可见应用窗口的元数据识别。
2. 游戏横屏切换时焦点标记/窗口缓存未及时稳定，旧判定漏掉仍可见的游戏窗口。新增该场景回归检查；按应用窗口层级识别并刷新缓存。
3. 小米15上离开小屋后检查出现暂停，回小屋才继续。前台服务运行本身仍不足；将伴学小屋的省电策略从「智能限制后台运行」改为「无限制」后，视频和横屏原神的拦截/确认返回桌面才连续通过。该设置按单个应用修改，产品提供系统设置引导；未改手机整体电量策略。
4. 游戏开始横屏后，按旧方向构建的面板会裁切按钮。按覆盖层实际可用高度重新布局，容器支持滚动，覆盖刘海区域。

番茄ToDo的借鉴范围是白名单、专注期间维持保护、权限引导与用户确认流程。开发者在小米商店的介绍公开了学霸模式和白名单搜索；权限列表含悬浮窗、开机启动和防休眠等。公开介绍不足以证明它的Android底层实现；本项目不宣称复制其内部代码，也不照搬其全部权限。当前采用Android公开无障碍窗口接口和专注期间前台服务，没有接入大模型/Agent。

- [番茄ToDo官网产品介绍](https://www.tomatodo.cn/)
- [Android官方无障碍服务接口](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)
- [Android前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)

交付以最终安装包的真机验证记录为准。一次成功、权限已开、编译成功或逻辑测试通过，均不能代替上述完整流程。多品牌适配、长时间耗电和停用/强停恢复另需验证。

2026-10-15 补充：已实际核查 OpenTimeLimit、DetoxDroid、Curbox 和 HyperOS accessibility guard 的服务、权限及恢复源码，详见[固定提交研究](research/2026-10-15-open-source-protection.md)。本机此前遗漏自启动条件；开启后单卡上划变为普通回收，可由系统重绑现有服务。官方机制、配置步骤及结果边界见[最近任务划除与后台设置](最近任务划除与后台设置.md)，最终同包验收见[0.2.7 记录](validation/0.2.7-device-checks.json)。历史失败不改写，真正强停不宣称已抵抗。
