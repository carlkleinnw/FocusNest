# 扩展接口与页面组件

## 第一版边界

代码中的接口均是Dart模块契约，尚未部署HTTP接口。模型与Agent未接入，没有模型密钥、网络调用或自动执行智能建议。组件与业务服务通过Riverpod注入，后续增加实现即可进行替换。接口版本目前为1。

## 契约

| 接口 | 提供的能力 | 第一版实现 |
| --- | --- | --- |
| ContextPort | 读取计划、最多100条历史、会话、宠物、休息日与规则 | AppController.readContext，返回JSON兼容快照 |
| ActionPort | upsertPlan、setRest | AppController；统一验证30分钟门槛、标题、提醒时间和休息日期 |
| IntelligencePort | suggest，异步生成建议 | DisabledIntelligence，available=false |
| EventPort | 订阅应用事件 | DemoEvents，内存广播流 |
| DevicePort | 应用/解除专注限制 | SimulatedDevice，simulated=true |
| ClockPort | 读取当前时间 | DemoClock，真实经过时间加虚拟偏移 |
| DataRepository | 提供当前快照并保存修改 | MemoryRepository；内存同步快照 |

业务操作返回统一的OperationResult：ok、code、message。模型服务返回建议，不接收任意状态写入。

## Agent接入方式

1. 通过ContextPort获得用户授权范围内的上下文。
2. 将上下文交给未来IntelligencePort适配器；密钥保存在服务端。
3. 校验外部返回的字段、长度、类型和动作名称。
4. 向用户展示具体建议，确认后通过ActionPort调用已允许的动作。
5. 订阅事件获取结果；重试创建计划时沿用同一个计划ID；休息安排使用setRest(day, enabled)，重复设置不会把日期意外切换回去。

当前可订阅：plan.changed、plan.deleted、focus.started、focus.completed、focus.cancelled、rest.changed、allowlist.changed、pet.interacted、pet.died、pet.adopted、day.advanced、demo.reset。

未来HTTP适配器应加请求ID、超时、重试、输入验证和用户确认凭据；不是现在已经实现的能力。Demo快进与重置不在ActionPort中。Agent没有直接喂食、复活、改生命值或绕过计时的工具。

## 真实设备与存储

- DevicePort由Kotlin/Swift平台通道实现，能力需要在真实设备上验证；网页演示没有系统级限制。
- 当前DataRepository提供同步内存快照。接入Drift时先异步加载数据库并初始化缓存，再由仓库同步给业务层；可靠异步落盘、错误恢复和迁移属于后续实现。
- 同步云端和后台Agent执行需另外定义服务端权限及数据同步协议。
- 饥饿当前由演示页推进日期结算。正式版需要在启动/恢复时根据已存日期补算，不能依赖后台计时器持续运行。

## 可复用组件

- PageFrame：所有页面一致的标题、说明、内容宽度和滚动布局。
- SurfacePanel：内容面板。
- MainButton：主要操作按钮。
- StatusPill：状态标签。
- EmptyPanel：空状态与状态引导。
- StatBlock：统计数字。
- PlanCard：计划显示、编辑和选择入口。
- PetPortrait / drawPet：小屋、专注、领养、悬浮预览复用同一角色绘制。
- RoomScene：Flame场景封装，只处理动画和输入反馈。
- AppShell：桌面侧栏、手机底部导航与更多菜单。

## 所用官方原则

[Flutter架构建议](https://docs.flutter.dev/app-architecture/recommendations)：分层、不可变状态、单向数据流、仓库和依赖注入。

[Flutter性能指南](https://docs.flutter.dev/perf/best-practices)：小组件复用，避免在build中创建计时器、读取数据库或做昂贵计算。

[Riverpod依赖替换](https://riverpod.dev/docs/how_to/testing)：用接口实现替换模拟服务。
