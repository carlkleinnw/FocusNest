# 扩展接口与页面组件

## 0.3.2 密钥查看与网页同源接口

`WebPlannerGateway`调用新版启动器提供的本地服务：`GET /api/agent/settings`仅返回是否配置、模型和bridgeVersion（当前2）；`POST /api/agent/configure`接收key/model/remove，在进程内存设置或移除密钥；`POST /api/agent/request`接收messages并请求DeepSeek官方HTTPS接口。无密钥不调用上游，保存也不发起模型请求。服务只绑定127.0.0.1，拒绝非本机Host、跨站Origin与非JSON写入，不在日志中输出密钥。

按用户要求增加独立`SavedKeyReader.readSavedKey`能力：设置页默认显示掩码，只有点击眼睛才调用网页`POST /api/agent/reveal`或Android通道`revealKey`，返回已保存密钥到当前输入框。普通settings/configure响应仍不包含密钥；reveal不允许GET、跨源或跨站请求，响应no-store。关闭页面清理控制器引用，不持久写入浏览器存储；Android仍从Keystore解密，网页仍从服务内存读取。该能力只供设置页显隐，不进入规划/复盘上下文或快照。

网页使用条件导入与`package:web`的fetch连接同源服务，避免在浏览器发送DeepSeek鉴权头或受上游CORS约束。首次保存网页密钥关闭演示与自动复盘；刷新通过配置标记恢复真实网关选择，计划数据仍为网页内存演示。404/405/501等缺少接口的状态提示使用新版启动器，保存失败展示经过网关清理的具体原因。

> **0.3.0 当前约定（2026-10-16）：** 用户已授权接入 DeepSeek，主流程收敛为今日计划、AI规划、沉浸专注、复盘，设置独立。本文下方的0.2内容作为历史机制说明；其中“AI仅预留/禁用”“宠物阻止专注”“未完成任务待手动调整”等旧产品边界不再适用。以[核心功能重构](核心功能重构.md)和当前源码为准。

当前新增 `PlannerGateway`（request/settings/configure），Android `focusnest/agent_v1` 通道实现密钥加密和DeepSeek HTTPS；旧的 `IntelligencePort` 禁用适配保留兼容。上下文与快照现为3，兼容读取快照2，原生保护通道和事件仍为1。新API支持生成草稿和受校验的计划导入，不允许模型直接修改会话或保护规则。复盘由 `ReviewEngine` 核算、选择证据并在成功保存后清理来源。设置首次保存密钥开启自动复盘，用户可关闭；运行/恢复期间处理积压，不承诺完全关闭时后台执行。

## 0.2 历史约定与机制
## 第一版边界

代码中的接口均是Dart模块契约，尚未部署HTTP接口。模型与Agent未接入，没有模型密钥、网络调用或自动执行智能建议。组件与业务服务通过Riverpod注入，后续增加实现即可进行替换。上下文与本地快照版本为2；事件和原生通道版本为1。

## 契约

| 接口 | 提供的能力 | 第一版实现 |
| --- | --- | --- |
| ContextPort | 读取计划、最多100条历史、会话、宠物、休息日与规则 | AppController.readContext，返回JSON兼容快照 |
| ActionPort | upsertPlan、upsertGoal、upsertMilestone、setRest | AppController；统一验证时长、容量、截止日期和任务关联 |
| IntelligencePort | suggest，异步生成建议 | DisabledIntelligence，available=false |
| EventPort | 订阅应用事件 | DemoEvents，内存广播流 |
| DevicePort | 读取应用、权限检查、开启/解除专注限制 | 网页SimulatedDevice；手机AndroidDevice通过平台通道连接原生服务 |
| ClockPort | 读取当前时间 | 网页DemoClock；手机RealClock |
| DataRepository | 提供当前快照并保存修改 | 网页MemoryRepository；手机AndroidRepository缓存与顺序SQLite写入 |

业务操作返回统一的OperationResult：ok、code、message。模型服务返回建议，不接收任意状态写入。

## Agent接入方式

1. 通过ContextPort获得用户授权范围内的上下文。
2. 将上下文交给未来IntelligencePort适配器；密钥保存在服务端。
3. 校验外部返回的字段、长度、类型和动作名称。
4. 向用户展示具体建议，确认后通过ActionPort调用已允许的动作。
5. 订阅事件获取结果；重试创建计划时沿用同一个计划ID；休息安排使用setRest(day, enabled)，重复设置不会把日期意外切换回去。

当前可订阅：plan.changed、plan.deleted、goal.changed、stage.changed、task.progress、capacity.changed、focus.started、focus.completed、focus.cancelled、rest.changed、apps.initialized、allowlist.changed、pet.interacted、pet.died、pet.adopted、day.advanced、demo.reset。事件名以 `lib/core/controller.dart` 的发布点为准；当前 payload 只带 sessionId 和 petGeneration，不能假设包含完整任务、目标或进度。事件是内存广播，不是持久化消息队列，没有离线补发保证。

未来HTTP适配器应加请求ID、超时、重试、输入验证和用户确认凭据；不是现在已经实现的能力。Demo快进与重置不在ActionPort中。Agent没有直接喂食、复活、改生命值或绕过计时的工具。

## 真实设备与存储

- Android通道为focusnest/device_v1，提供apps/status/settings/backgroundSettings/load/save/start/stop；backgroundSettings打开本应用信息页，0.2.7引导本人同时检查小米自启动与省电策略。status仍只检查现有保护连接等状态，不认证厂商自启动设置。没有快进或启用系统权限的后门。当前没有iOS原生适配器。
- 本地快照与ContextPort上下文版本为2，事件和平台通道版本为1。快照内allowlistSchema=1表示allowedApps是用户明确放行的应用包名；旧快照没有该标记时默认空白名单。仓库先异步加载，再提供同步缓存；普通编辑按队列写入。专注开始/完成/取消的规则与状态在同一SQLite事务保存。
- 同步云端和后台Agent执行需另外定义服务端权限及数据同步协议。
- 手机启动与恢复时按已存日期补算。服务到时独立放行，前端重新打开后补结算。网页继续使用虚拟时间。

## 后续扩展接在哪里

现有接口在 `lib/core/ports.dart`，由 `lib/core/controller.dart` 声明 Riverpod provider，Android 实现在 `lib/data/android_adapters.dart`，网页替身和禁用智能实现在 `lib/data/demo_adapters.dart`。`lib/main.dart` 在 Android 启动时注入真实时钟、仓库和设备。新增实现沿此入口注入，页面继续读取状态和发送业务操作，避免在页面内直接调用模型、网络或数据库。

| 后续需求 | 已有落点 | 实施时仍需补齐的部分 |
| --- | --- | --- |
| 新页面或新的宠物表现 | `lib/pages`、`lib/ui`、`lib/pet` | 复用页面框架和角色绘制；新业务规则留在 core，Flame 不接管计时和存储 |
| 学习建议或模型服务 | `IntelligencePort` + `ContextPort` | 用户另行授权后实现服务端适配、最小上下文、超时和返回校验；维持默认禁用实现，建议先展示再确认 |
| Agent 执行动作 | `ActionPort` + `OperationResult` | 当前只允许四种计划/目标/阶段/休息操作；新增动作要显式定义类型、输入约束和确认流程，不开放任意控制器或状态写入 |
| 云同步或替换本地存储 | `DataRepository` + 快照编解码 | 当前 load 返回已初始化缓存，save 不返回 Future；云端需要异步初始化、失败状态、冲突策略和迁移，不能把远程请求直接塞进同步 load；保持专注规则与会话事务一致 |
| 其他平台的应用保护 | `DevicePort` | 单独实现该平台的原生能力、授权和恢复；网页模拟通过不代表真机能力，不能假设 iOS 与 Android 对等 |
| 记录导出、统计或提醒 | `ContextPort`、`EventPort` | 现有事件不含完整业务数据且不会持久重放；先定义最小数据和一致性要求。计划后台提醒尚无调度接口，需要独立定义权限、取消和到时语义 |
| 可重复规则检查 | `ClockPort` | 测试注入时钟；Android 用户数据继续使用真实时钟，不能把演示快进开放给真实专注或 Agent |

这些是扩展位置和后续工作边界，不表示上述功能已实现。优先为具体需求增加小接口和适配器；不预建通用插件引擎、空实现页面或无限动作入口。

## 扩展时的兼容约定

1. 上下文和本地快照当前为版本 2，事件与原生通道当前为版本 1。新增字段要定义旧数据缺省值；改变字段语义、删除字段或改变平台调用参数时，显式评估版本及迁移，不靠覆盖安装自动清空数据。
2. 每次扩展都保留 `DisabledIntelligence` 和网页替身。第一版未获新的实施指示时不启用模型或 Agent，不把模型密钥放进 Flutter、APK、网页或仓库。
3. 会话开始、完成和取消仍走现有控制器与原生事务；保护名单在会话开始时冻结。新增模块不能直接喂食、改死亡判定、缩短真实计时或修改用户进行中的会话。
4. 新功能按一个核心任务放到对应页面，共用可复用组件。事件订阅在所属生命周期释放；需要长期保存或可靠重试时另建明确契约，不假设内存广播具备这些能力。
5. 针对新增适配器验证成功、拒绝、失败与恢复路径；涉及原生保护时使用最终同一 APK 做真机验收。文档记录已有能力与计划能力，核心未通过则保持候选状态。

## 可复用组件

- PageFrame：所有页面一致的标题、说明、内容宽度和滚动布局。
- SurfacePanel：内容面板。
- MainButton：主要操作按钮。
- StatusPill：状态标签。
- EmptyPanel：空状态与状态引导。
- StatBlock：统计数字。
- PlanCard：计划显示、编辑和选择入口。
- PetPortrait / drawPet：小屋、专注、领养、悬浮预览复用同一角色绘制。
- RoomScene：Flame场景封装，只处理动画和输入反馈。
- AppShell：桌面侧栏、手机底部导航与更多菜单。

## 所用官方原则

[Flutter架构建议](https://docs.flutter.dev/app-architecture/recommendations)：分层、不可变状态、单向数据流、仓库和依赖注入。

[Flutter性能指南](https://docs.flutter.dev/perf/best-practices)：小组件复用，避免在build中创建计时器、读取数据库或做昂贵计算。

[Riverpod依赖替换](https://riverpod.dev/docs/how_to/testing)：用接口实现替换模拟服务。
