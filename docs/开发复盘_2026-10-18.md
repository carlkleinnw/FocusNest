# AI 追问修复与技能去重复盘

本次回顾的是 2026-10-17 的 0.4.1 追问修复与交付。应用基线为 `914af97` / `v0.4.1-demo`，事实依据是[验证记录](validation/0.4.1-checks.json)及本次对话；2026-10-18 仅整理技能与文档，应用仍为 0.4.1+16。

## 有效经验

1. **找完整控制链。** 三轮限制同时存在于提示词、控制器、页面说明和旧测试中。只改提示词，第四轮仍会被程序拒绝；只改控制器，模型仍可能按旧提示提前生成计划。原始目标与补充其实已经随请求传递，不应先归因于模型忘记上下文。
2. **澄清轮数与执行预算分开。** 用户要求按需求完整程度追问，并不要求取消工具迭代、输入长度、输出字段或事务校验。保留旧 `rounds` 数据作记录，避免无必要的快照迁移。
3. **用不同证据回答不同问题。** 固定响应证明程序接受超过旧上限的结果；真实模型证明合成需求下的语义流程；最终 APK 另验发布形态、重启续聊与明确后保存。72 项 Flutter 测试、23 项原生检查、模拟器真实六轮以及正式包五轮，各自的适用范围不能互相替代。
4. **交付阶段分开核对。** 分支与附注标签推送成功后，附件曾因 Python 的证书链失败而中断。Windows 客户端只读请求验证成功后恢复传输，保持 TLS 校验；五个附件下载哈希匹配后才报告交付完成。

## 我的失误与纠正

| 失误 | 这次观察到的事实 | 下次改变的动作 |
| --- | --- | --- |
| 初步定位后过早宣布修法 | 用户连续强调先看项目、以源码为准；当时还没完整核对对话、网关与状态流 | 先分清诊断/实施范围，定位控制链再给结论；只读阶段不启动修改 |
| 技能中沿用旧产品规则 | 现有技能仍写首版禁用 AI、宠物影响专注，当前源码已进入计划 Agent 主流程 | 产品规则由当前项目文档维护；技能保留代码入口与稳定边界，清理历史阶段常驻约束 |
| 测试驱动忽略目标包配置 | 本机服务有配置，最终 APK 初始请求却提示未配置 | 安装/切换包后先查目标包配置并验证连接；未取证时不认定具体是谁清掉配置 |
| 以为输入命令成功就输入完整 | 一次长文本只进入了前 137 字符 | 比较真实字段与预期合成输入后再发；必要时短文本或分段输入 |
| 用固定等待判断重启就绪 | 等待三秒后的定位失败，随后目标包才进入前台 | 对目标包、页面和控件做有时限的就绪检查；状态真实连续才从检查点续跑 |
| UI 成功信号偏弱 | 临时脚本用过问号和输入框清空；后续还靠新消息截图与实际任务数量核对 | 通用验收以新结果类型、会话变化和实际存储为准，旧气泡标点不能证明新回复正确 |
| 工具读取范围仍偏宽 | 全量 GitHub 工具元数据及多份长文档读取出现截断 | 这是[前次复盘](开发复盘_2026-10-16.md)已有规则执行不足，不再叠加同义提示；下次按工具名和文件片段缩小读取 |

编译错误、未使用导入已有测试编译和静态检查能够发现，本轮继续用现有检查，没有为同一问题再添一套 CI 或规则。资源紧张时仅在构建结束后停止了本轮构建守护进程，没有关闭用户应用；不将此作为所有慢测试的默认修法。

## 提炼到已有技能

| 既有入口 | 本次变化 | 避免重复的方法 |
| --- | --- | --- |
| `diagnosing-bugs`（用户技能） | 新增 `references/llm-conversation.md`，覆盖 AI 产品的提前停止、上下文与过早执行；入口增加条件指针 | 沿用现有调试入口；不另建 AI 调试、无限追问或需求采访技能 |
| [focusnest-evidence-first-delivery](../.agents/skills/focusnest-evidence-first-delivery/SKILL.md) | 新增[模拟器测试环境与驱动](../.agents/skills/focusnest-evidence-first-delivery/references/emulator-runtime.md)；在原发布参考中补证书链区别 | 模拟器、原生保护、长时计时和附件发布各按分支读；签名、哈希与认证规则仍在原参考中 |
| `focusnest-product-rules`（用户技能） | 精简为当前规则来源、业务代码入口和数据边界；移除旧阶段的硬性产品要求 | 不复制 README/AGENTS 的整套产品规则；调试和交付转交原有专用入口 |

技能名称、frontmatter 描述和自动调用元数据均保持不变，新增常驻技能描述为零。三个 SKILL.md 的总字符数由 10919 降到 10632，减少 287；这是字符计数，不是模型 token 测量。新增细节放在两份按条件读取的参考中。

项目交付技能与已安装用户副本同步；同名技能按项目规则只读取最具体的一份。用户技能原文件已备份到既有 E 盘备份目录，可迁移包保留每个技能的完整相对引用，不携带手机数据库、密钥、截图、APK 或临时传输脚本。

## 验证与边界

- 既有校验器通过三个技能及交付技能的用户副本；Markdown 相对引用、项目/用户副本、原有描述与自动调用元数据核对一致。
- [技能检查记录](validation/0.4.1-retro-skills-checks.json)记录入口字符数、元数据及副本核对；可迁移包为本地 `dist/FocusNest_Skill_Updates_2026-10-18.zip`，附带文件清单和哈希，用户已安装技能的更新不作为新增自动发现入口重复安装。
- 路由静态演练：AI 轮数/上下文故障读取 LLM 参考；普通 CRUD 调试不读取它；Android 保护故障仍走 Android 调试技能；模拟器配置/输入/就绪问题读取模拟器参考；附件 TLS 错误只读取发布参考；用户要求先看源码时保持只读。
- 本轮没有修改运行代码、应用版本、推送脚本或全局 AGENTS.md，没有安装依赖、重建 App 或操作设备。结构校验与路由演练不等于已在另一项目完成运行验收。
- 文档/技能修订使用新的附注标签 `v0.4.1-demo.1`，保留原应用标签及 APK。通用部分随技能包提供，迁移时用目标项目规则替换 FocusNest 专属约定。
