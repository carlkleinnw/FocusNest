# 伴学小屋稳定性补验复盘

依据本次对话、`v0.2.7-demo.2` 的代码与验收摘要，以及此前保留的 0.2.6/0.2.7 对照记录。本文记录可复用的决策经验；手机即时状态、当前分支和工具路径仍应在下一次任务重新核对。

## 本轮实际完成

运行包保持 0.2.7+11，没有改运行代码、重建或安装 APK。完成最终包独立新会话 30 分钟、20 分钟锁屏的 39 次采样、锁定期间到期、未重开小屋的解锁放行、恢复结算及独立会话两轮退出；核对已有 7 类接口和 17 个事件，补上扩展边界。静态检查、28 项 Flutter 测试、23 项原生规则检查通过，四个发布附件下载核验通过。

本机结果仍依赖 Xiaomi 15 / Android 16 / 指定 HyperOS 固件、自启动开启、省电无限制和无障碍连接。USB 供电锁屏不能代替耗电或深度待机验证；到期精确解除延迟未测。详见 [本轮摘要](validation/0.2.7-stability-2026-10-16.json)，原历史失败记录保持原样。

## 有效做法

| 做法 | 为什么有效 | 类似项目如何复用 |
| --- | --- | --- |
| 先核对代码、工作树和远端，再用交接选检查项 | 避免历史快照被当成现在状态 | 开始时分开说明本轮重查、历史证据和未知项 |
| 先检查完整设备条件，再考虑更强守护 | 此前只开省电无限制仍遗漏自启动；配置改变了本机划除路径 | 厂商设置、无障碍绑定、stopped 和实际拦截逐层对照，不先堆高权限方案 |
| 对最终安装 APK 核对哈希与证书 | 相同版本号不足以证明同包，证书不一致会阻止覆盖 | 保留原签名和数据；没有必要时不为了补验重装 |
| 自由专注单独测试 | 保留原用户会话、任务和记录 | 先看当前会话，只结束自己创建的测试，真实测试结果保留 |
| 启动、完成、取消与恢复分别验收 | 跨升级到期和新包独立运行提供不同证据 | 最终包新会话真实跑完，恢复后核对记录与奖励，取消另外检查 |
| 复用已有接口并写清缺口 | 现有分层已可扩展，无需增加空壳系统 | 核对适配器和注入点，明确异步存储、事件可靠性及平台能力边界 |
| 只提交必要证据与文档，分阶段核对交付 | 软件包不变时避免无意义构建；网络失败不掩盖已完成阶段 | 验证、提交、新附注标签、远端引用和附件下载摘要分别报告 |

## 本轮踩坑与具体纠正

1. **把 Asleep 当成唯一灭屏状态。** 本机曾报告 Dozing 与物理屏幕 OFF。今后分开读取用户锁定、电源和显示状态；这里的 Dozing 不证明深度设备空闲模式。
2. **把通知亮屏、实际解锁和保护失效混在一起。** 本轮前期观察被打断，最终有效片段里也有两次亮屏采样但仍锁定。今后通知亮屏单独计数，真正解锁打断连续锁屏；工具或用户干扰不直接归为产品失败。
3. **没有先排好锁屏和会话的时间。** 排查与重新计时消耗了会话余量，最终长锁屏跨过到期。今后先安排同一时间线；若要测原会话长锁屏后仍拦截，启动前预留足够时长和解锁操作窗口。跨到期时就按跨到期范围报告，不改进行中的计时。
4. **采样循环在终点直接退出。** 最后一条运行采样为 15:56:49，首次停止快照为 15:58:30。实际到期解除发生在哪一刻无法从这些点确定。今后终点、超时和异常退出都补最后一次状态采样，并记录状态转换的时间区间。
5. **恢复工作后沿用旧界面坐标。** 中断后手机已经换到其他应用，我仍执行了一次旧的滑动并误采了第三方界面，随后删除该图并重新核对。今后每段触摸和截图前都确认预期前台及当前页面，变化后重新定位；截图函数同样要有前台校验。
6. **网络客户端失败后重复走同一路径。** Python HTTPS 先后握手超时和 EOF；现有 Windows curl 路径完成剩余传输。今后先区分传输故障与认证/远端状态，再做有界重试或更换已有客户端；已成功附件按摘要复用，不覆盖标签，不关闭 TLS 校验。
7. **工具发现与读取输出过宽。** 按所有工具的共享描述搜索，曾输出大量无关元数据；多份长文件合并读取也发生截断。今后先按工具名缩小范围，只展开选中 schema；按总输出预算拆分独立读取，避免因截断遗漏约束。

## 下次执行时的简短顺序

核对实际状态 → 识别用户会话 → 明确本轮证据范围并排时间 → 同一最终包测试 → 中断后重查界面 → 终点补采样 → 分开记录通过/失败/未知/干扰 → 在授权范围内提交标签并校验交付。

新写长时测试驱动时，优先将“前台不符就拒绝操作/截图”和“到终点仍读取最后状态”做成实际检查。本轮只把方法提炼进技能，没有把带本机坐标和设备标识的临时测试脚本发布为通用工具，也没有新增 CI 或运行依赖。
