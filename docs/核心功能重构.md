# 0.3 核心功能与实现边界

> **0.4 当前增补（2026-10-17）：** 追问改为模型按语义判断；AI 可直接查询、创建、修改、删除计划。计划页分日／周／月／季度／总目标，每层支持手动管理。参见 [Agent与分层计划](Agent与分层计划.md)，该文替代下文0.3的固定草稿流程与平铺路线说明。

> 0.3.2补充：设置页可填写API密钥，经同源本地服务调用DeepSeek；按用户要求，保存后有掩码，点击眼睛可读取完整值，刷新后也支持。网页密钥仅在服务内存，不写文件或浏览器存储；Android仍使用Keystore加密。保存不调用模型，首次网页保存关闭演示与自动复盘。本轮真实API与模拟器验证见[0.3.2检查](validation/0.3.2-checks.json)。

2026-10-16 按用户最新需求，将主流程精简为「今日计划 → AI 规划 → 沉浸专注 → 复盘」，设置独立放置。以新需求替代 0.2 的“智能模块仅预留”边界。宠物、小屋、休息和领养的历史模块保留源码与旧数据兼容，移出主导航，宠物状态不再阻止学习。

## 六个核心功能

| 需求 | 本版行为 | 复用与新增 |
| --- | --- | --- |
| DeepSeek Agent 制定计划 | 输入目标，最多3轮追问；月目标、周安排、每日具体任务组成草稿；展示假设，确认后一次入表；支持补充要求重新生成 | 复用 Goal、Plan、Riverpod、SQLite；新增 PlannerGateway 与受限的 JSON 计划校验 |
| 计划增删改查 | 手动新增、编辑、确认删除；今天/全部/按日期和关键词查询；目标与完成量为可选项 | 复用编辑器与控制器，简化计划页面 |
| 每个任务进入沉浸 | 今日未完成任务可进入，记录 planId；时长可选或自定义；结束不会自动勾选任务 | 复用原生保护、会话存储、完整完成与两轮退出流程 |
| 独立沉浸 | 不关联任务的自由专注，自填主题；30/45/60/90分钟以及30—180分钟内的自定义整数 | 与任务专注共用引擎；沿用原有原生时长边界 |
| 完成记录与周期压缩 | 勾选时保存实际确认时间；周/月/季/年逐级总结；已校验的总结和删除来源明细放入同一次本地快照保存 | 新增 ReviewEngine、结构化统计和来源 SHA-256；复用 SQLite 事务写入 |
| 自动顺延 | 每次推进日期，将未完成过期任务顺延到新的一天；原 ID、原定日期、部分完成量保留，累计顺延次数；删除后不再顺延 | 复用启动恢复和每秒计时检查；完成任务不顺延 |

一次最多生成未来366天、366项任务；允许休息日。计划按日期分配容量，模型输出还会检查标题、时长、真实日历日期、周区间、月/周/日覆盖、重复任务和已有安排。超容量不会悄悄截断或部分入表。自动顺延导致某日超量时显示提醒，保留任务，允许调整。

## 独立设置与密钥

设置页提供 API 密钥填写、显隐、模型选择、保存、移除、真实连接测试、每日可用时间、自动复盘开关、明确标识的 AI 演示模式、专注保护入口。

Android 使用用户自有密钥（BYOK），由 Android Keystore 中的 AES 密钥进行 AES/GCM 加密，仅把密文和 IV 放入应用私有偏好。API 密钥不放到 AppState、SQLite 快照、网页构建、源码、日志或测试证据。应用禁止系统备份；卸载会失去本地数据和密钥。重新编译到另一台设备不携带该密钥。

请求仅发送到 `https://api.deepseek.com/chat/completions`，不接受自定义主机、不跟随重定向。连接与读取有超时，错误不返回服务端原始正文，避免泄露凭据。模型默认使用查阅官方接口文档时支持的 `deepseek-flash`，也可选 `deepseek-v4-pro` 或兼容名称 `deepseek-chat`；兼容名称实际可用性由连接测试确定。

发送规划请求时包含用户目标对话、每日容量、已有待办每天占用的分钟数及最多12份最近复盘的关键事实。发送复盘请求时只包含本次周期的完成事实与统计，不发送应用名单和无关系统数据。请求会产生用户账户的 API 费用。演示模式使用固定 Python 采集计划，不联网，也不会在真实调用失败时自动伪装成成功。

## 总结准确性与清理顺序

1. 完成事实由用户勾选建立，以实际确认日期归档；完整专注和提前退出分别统计。虚拟专注不计入真实时长。计时完成不等于任务完成。
2. 原始任务的具体标题与确认日期作为可引用事实；AI 最多选择6条关键事实的 ID，程序检查 ID 均来自输入且不重复，再原文展示。模型不能改写这些历史事实和统计数。
3. AI 自由文本只放在明确标识的“下一步建议”，不作为完成证据，也不进入父级统计。
4. 周按周一开始，遇月末拆成两个不重叠区间。自然月、自然季度和自然年仅消费完全包含的子周期。所有区间使用左闭右开，避免跨月/跨年重复计算。
5. 任务数、完成量、完整专注次数和分钟数、提前退出分钟数、按目标的完成量由程序计算并逐级相加。父级保留压缩来源的 SHA-256 和累计来源数量。哈希用于来源一致性记录，不能在明细删除后重建全部明细。
6. 网络请求前记录来源指纹，返回后重新检查。用户期间修改记录则放弃本次清理。模型字段错误、引用不存在、请求失败或写入失败时保留未成功总结的来源。
7. 新总结与移除对应来源在同一快照内保存；Android 写入成功后才更新可见状态。失败回到原状态。重试不会重复处理已经移除的同批来源。
8. 待办永不被总结清理。旧版已完成任务没有真实完成时间，标为日期未知并保留，不编造时间。目标路线只保存月/周安排与假设，不另存每日任务副本。

压缩有信息损失：所有总数精确保留，最多6条代表性任务原文保留，非关键逐项内容会移除；父周期会取代子周期。压缩后的明细无法再逐项撤销。关闭自动复盘后仍可手动对结束周期执行压缩。跨日未结束的当前周期不清理。

自动复盘在应用运行/恢复时检查，距上次尝试至少15分钟；一次最多追赶64个周期。应用完全关闭时不保证在周末午夜联网执行，下次打开补处理；离线、无密钥或系统限制时不删除待总结数据。设置与页面明确说明此行为。不会在后台偷偷唤醒手机或更改保护权限。

## 架构与迁移

- Flutter 与 Riverpod 保留；页面发送操作，控制器处理，ReviewEngine 负责纯统计与周期，PlannerGateway 负责模型边界，Android PlannerBridge 负责系统密钥和 HTTPS。
- 本地快照升级到3，读取2和3；不清数据迁移。`ContextPort` 输出版本3并加入压缩复盘。原有禁用智能接口仍保留兼容；新 Agent 使用明确的 PlannerGateway，不开放任意控制器动作或设备工具。
- 原生 `focusnest/device_v1` 的保护逻辑与时间边界继续沿用，独立 `focusnest/agent_v1` 提供 `settings/configure/request/revealKey`；settings只返回是否配置和模型，只有用户主动点击眼睛时revealKey读取密钥给当前设置页。
- 计划导入与复盘是需要持久保存结果的路径，等待本地写入；普通编辑沿用串行保存并显示存储失败提示。
- 新建 Android 数据为空，避免将演示任务与个人真实任务混淆；覆盖安装保留原计划、白名单、会话和历史数据。

## 复用与开源参考

优先复用本仓库已有实现，避免引入第二套任务数据库或大型 Agent 框架。调研了 [Tasks.org](https://github.com/tasks/tasks) 介绍的任务、完成与日期管理范围；其原生技术栈与当前 Flutter 架构不同，本轮仅作为功能参考，未复制其源码或增加相应运行依赖。

API 与安全实现依据 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Android Keystore](https://developer.android.com/privacy-and-security/keystore)。JSON 可解析不等于业务数据正确，因此仍在本机逐字段校验并进行容量和周期核算。
