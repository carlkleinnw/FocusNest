# 0.2 原生专注与计划联动

## 体验方式

Android使用真实时钟和本机SQLite；网页保留虚拟时间、模拟应用列表和刷新重置。初始学习计划、历史与宠物仍为演示样例，真实新增记录另行保存。

手机进入「更多 → 应用锁定 → 前往系统开启权限」，在无障碍设置找到「伴学小屋专注保护」。权限由用户本人开启。页面显示「保护权限已开启」后才能开始原生专注。

读取可启动应用列表，默认推荐限制游戏、视频、音乐及少量已知娱乐应用。分类可能不完整；用户应确认名单，开启开关表示允许。电话、默认拨号器、桌面、设置和系统必要组件始终允许。专注期间名单不能修改，新安装应用需结束后刷新并检查。

打开限制应用时，原生服务显示提醒并返回桌面；不结束其他应用进程。无障碍服务只订阅窗口切换的包名，不读取窗口内容，不截图、不上传应用列表。

普通提前退出和安卓系统返回键共用两轮确认。返回桌面并不取消专注。退出与会话结果一起落盘，避免中断后把取消的专注误算为完成。

## 计划联动

长期目标记录总量、单位、截止日期；阶段记录分量和阶段期限。每日计划选择目标与阶段、日期、计划时间、数量和专注时长。总安排不能超过目标或阶段数量，日期不能超过对应期限，每日时长不能超过可用时间。

用户手动记录每日任务的实际完成数量；同一任务修改进度采用覆盖，重复保存不重复累计。长期目标与阶段按任务完成量动态汇总。计时完成不直接认定任务完成；手动勾进度不会喂食。

未完成的过去任务进入「待调整」，用户决定如何重新安排。不会自动覆盖原计划或无限堆积到明天。计划时间目前只供安排参考，没有后台通知或定时自动开始。

## 存储与恢复

数据在应用私有SQLite内保存，保存失败展示提示，加载失败保留已有数据并提供重试。启动后按保存日期补算未喂食天数与休息日，先结算此前已到时的专注，再推进下一天。

原生专注规则与开始/完成/取消状态使用同一个SQLite事务保存。前端保存队列按顺序写入；会话操作先等待队列，防止旧快照覆盖新会话。到时后服务独立放行，打开应用后补计记录与喂食。

普通计划编辑仍异步落盘；未完成保存时突然断电可能丢失最后一次修改。当前不是经过长期运行验证的正式版本。

## 当前边界

- 仅实现Android；网页不会拦截真实手机应用。没有iOS原生限制。
- 不能阻止用户关闭无障碍权限、强行停止、卸载或修改系统时间。
- 未实现设备所有者/kiosk、系统级禁止安装、阻止卸载或娱乐应用强制停止。
- 服务被系统或厂商后台策略停用会失去保护；UI在运行时检查权限。不同品牌需要分别真机验证。
- 应用分类是建议，不能保证自动识别所有娱乐软件，也不能区分同一应用中的课程和娱乐。
- 外部悬浮宠物仍未实现；小屋与应用内悬浮预览可互动。
- 智能接口保留，大模型与Agent未启用，无模型密钥和自动建议执行。
